RÉSUMÉ DES 3 NOUVEAUX SCÉNARIOS :
  1. Scénario GET  : Offre de Recrutement PFE (Action sensible exécutée en GET)
  2. Scénario POST : Facture Télécom PDF (Attaque 100% invisible via iFrame)
  3. Scénario IMG  : Forum & Mème (Attaque par balise <img src="..."> - Zéro JavaScript !)

================================================================================
SCÉNARIO 1 : MÉTHODE GET (Offre de stage PFE)
================================================================================
Dossier : csrf-tp-lan-2\1_scenario_get_recrutement

Lancement :
  cd "1_scenario_get_recrutement"
  .\run_demo.bat vulnerable

Déroulement de la démo :
  1. La victime (Ayoub) se connecte sur http://192.168.x.x:5000 (Ayoub / password123).
     -> Solde initial : 1 500 €.
  2. L'attaquant envoie le lien par mail/Teams :
     http://IP_ATTAQUANT:8081/stage_recrutement.html?target=IP_VICTIME
  3. La victime ouvre la page pour lire l'offre de stage rémunérée à 1 650 €.
  4. En coulisses, une redirection GET s'effectue vers /virement?dest=Hacker&montant=500.
  5. Résultat : 500 € débités du compte d'Ayoub !

Défense à montrer :
  .\run_demo.bat secure
  -> L'action est interdite en GET (405) et exige un formulaire POST avec Token CSRF.

SCÉNARIO 2 : MÉTHODE POST SILENCIEUSE (Facture PDF via iFrame)
================================================================================
Dossier : csrf-tp-lan-2\2_scenario_post_facture_pdf

Lancement :
  cd "2_scenario_post_facture_pdf"
  .\run_demo.bat vulnerable

Déroulement de la démo :
  1. La victime se connecte à son portail télécom sur http://192.168.x.x:5000.
     -> Adresse actuelle : "12 Rue de la Paix, 75000 Paris".
  2. L'attaquant envoie la fausse facture PDF :
     http://IP_ATTAQUANT:8081/facture_pdf.html?target=IP_VICTIME
  3. La victime regarde la facture de 79,90 € dans le faux lecteur PDF.
  4. L'iFrame invisible soumet en POST l'adresse du pirate en arrière-plan.
  5. LA VICTIME NE QUITTE JAMAIS LE FAUX PDF !
  6. Si on recharge le portail légitime : l'adresse a été détournée vers "666 Avenue des Pirates" !

Défense à montrer :
  .\run_demo.bat secure
  -> Rejet immédiat par Synchronizer Token Pattern (403 Forbidden).


================================================================================
SCÉNARIO 3 : BALISE IMAGE (Forum / Mème - Zéro Clic & Zéro JS !)
================================================================================
Dossier : csrf-tp-lan-2\3_scenario_img_forum

Lancement :
  cd "3_scenario_img_forum"
  .\run_demo.bat vulnerable

Déroulement de la démo :
  1. La victime est connectée sur son portefeuille solidaire (Solde : 2 000 €).
  2. Elle visite un forum étudiant avec un sujet sur les mèmes de code :
     http://IP_ATTAQUANT:8081/forum_photo.html?target=IP_VICTIME
  3. Elle voit la photo amusante du chat.
  4. Une balise <img src="http://IP_VICTIME:5000/don-rapide?dest=Association_Hackers&montant=200">
     invisible est analysée par le navigateur.
  5. Le navigateur envoie la requête GET avec le cookie de session pour charger "l'image".
  6. Résultat : 200 € débités SANS AUCUN SCRIPT JAVASCRIPT EXÉCUTÉ !

Défense à montrer :
  .\run_demo.bat secure
  -> Obligation stricte de la méthode POST avec jeton. Une balise <img> est inefficace !
